## Authentication and sessions

SEC-S004: Use WordPress identity with a vetted MFA integration for platform administrator, marketplace administrator and every seller/platform finance user. Step-up authentication within5minutes is required for payout destination change, payout approval, API-key issuance and privileged membership changes. Seller owner enrollment requires MFA before team invitation. Password recovery has uniform responses, one-time expiring tokens, revokes existing sessions after reset and does not bypass MFA. Lost-factor recovery requires equivalent identity proof and independent operator review; support cannot choose a customer's password. Proposed privileged idle timeout30minutes and absolute8hours; customer persistent sessions follow explicit store policy and device revocation. Session identifiers rotate on authentication/privilege change, use TLS-only Secure/HttpOnly cookies, and apply compatible SameSite settings verified with hosted payment redirects. Never log tokens.

SEC-S005: Cookie-authenticated mutations require CSRF protection plus authenticated identity, capability, membership, resource and field checks. [WordPress nonces](https://developer.wordpress.org/apis/security/nonces/) are not authentication, authorization or one-use replay protection, and the common guest ID needs a session-specific approach (SRC-S011). Use the native Store API's documented cart/session protection for commerce and a server-bound random guest session for custom private guest state. A supplied seller_id is a selector, never authority. Administrative REST and seller endpoints deny by default. Non-browser integrations use revocable scoped credentials, no broad administrator key; CORS allowlists exact origins, not wildcard credential access. Invalid credentials401, forbidden known resource403 or deliberately indistinguishable404, conflict409, invalid fields422, throttled429. Public errors expose a correlation ID only.

Cookie-authenticated WordPress REST reads also send the native `wp_rest` nonce (prefer the `X-WP-Nonce` header); without it the native authentication path treats the request as unauthenticated. This is distinct from the requirement for object authorization. See [official REST authentication](https://developer.wordpress.org/rest-api/using-the-rest-api/authentication/) (SRC-G011). Application Passwords inherit the integration user's capabilities; proposed route/resource restrictions require the project integration policy, not an assumed native per-token scope system. High-risk human approvals additionally require independent approver identity and fresh step-up evidence.

## Input and remote resource boundaries

SEC-S006: Validate schema/type/range/enum and reject unknown writable fields. Normalize Unicode without changing identifiers or prices. Contextual escape happens at rendering; sanitizing stored HTML does not replace escaping. Database access uses supported APIs/prepared parameters. Reject arbitrary serialized objects and executable settings; no shell input from imports. Redirect destinations are same-site relative or approved explicit hosts. Connector URLs allow HTTPS hosts verified against approved provider configuration; resolve and reject loopback/private/link-local addresses at each redirect and connection, cap redirects2/time10seconds/body10MiB, and enforce outbound network restrictions. Failed validation leaves prior data unchanged and creates no job.

## Upload and import policy

SEC-S007: Sellers may upload JPEG/PNG/WebP images up to10MiB and PDF manuals up to20MiB, at most20files/request; catalog admins may add vetted video through an approved media service. Check extension, MIME and parsed content, remove image metadata, reencode raster images, randomize storage names and store private evidence outside public media. Reject SVG, HTML, executables, archives and fonts from seller uploads. Administrator fonts require approved license and explicit safe format validation. Malware scanning quarantine is required for PDFs/evidence; scanner unavailable means pending and unservable, not automatic acceptance. Private download URLs are short-lived and resource-scoped; public manuals contain no customer or seller identity documents. Limits are provisional controls, configurable only by platform security policy.

CSV imports are <=10MiB/10,000rows per batch, have declared schema, reject formulas at export, and preview validation/errors before commit. No ZIP upload in baseline; a future archive adapter needs bounded expanded size, entry count, depth and traversal checks. Dry runs and imported changes retain seller scope, provenance and optimistic version checks.

SEC-S008: Global styles/templates require platform editor capability; sellers receive limited logo/color/text tokens within allowed ranges, no raw CSS/JS, unfiltered HTML, template editing or remote script embeds. Import/export uses allowlisted schema keys and excludes credentials, personal data and hidden capabilities. Unsafe URL schemes, CSS network imports and unlicensed fonts are rejected. A failed import is atomic with a readable field error and no permission widening. [WordPress security guidance](https://developer.wordpress.org/apis/security/) supports validation and context-specific output protection (SRC-S013); all limits above are proposed project decisions.
