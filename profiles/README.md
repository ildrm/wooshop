These are configuration manifests and clearly labelled synthetic fixture assets for three independent store profiles. The Outdoor, Smart Home and generic stationery examples use the same theme/plugin packages. Schema fields here describe profile data; importing them into the plugin's typed schema/evidence workflow remains separate work. Native product attributes in the fixture catalog are not certified evidence.

The additive fixture command requires both `wp_get_environment_type() === 'local'` and `WOOSHOP_LOCAL_FIXTURES === true`. It creates native simple, variable, grouped, external, virtual and downloadable examples, zero/unknown price and stock examples, enough real products for pagination, original labelled media, native pages/navigation and a reviewed-claim-free guide. It reuses stable fixture identities. It creates no orders, customers, sellers, reviews or subscriptions, sends no communications and transfers no funds. It never resets a database. The only content repair updates an importer-owned hero CTA that still matches its recorded/default catalog destination; explicitly edited merchant URLs and all surrounding content are preserved.

```sh
rtk proxy python3 tools/dev.py wp outdoor eval-file /workspace/tools/seed.php outdoor configure-profile
rtk proxy python3 tools/dev.py wp smart-home eval-file /workspace/tools/seed.php smart-home configure-profile
```

Use `neutral` only in a third independent local installation; importing a different profile into a site already labelled by this importer is refused. The repository development command currently addresses the two configured sites. No third runtime installation is claimed.

Initial configuration requires the explicit positional `configure-profile` marker and no `wooshop_profile_seeded` marker. Native user styles prevent first configuration. These isolated installations were created for this run; their other synthetic test products are retained. Reseeding preserves all later configuration and content edits. Omit the marker for an additive catalog-only seed. The new local fixture sets USD, test address context US:CA, no tax, shipping5.00 and native offline COD explicitly labelled as a test. These values are local fixtures, not jurisdiction, tax, fund-flow, warranty or business decisions. Applying a native style variation uses a new native `wp_global_styles` record; preexisting user styles prevent setup. After assigning native WooCommerce page IDs, the importer records and resolves the owned hero CTA against `wc_get_page_permalink('shop')`. Legacy fixture CTAs still pointing at the original `/shop/` route are migrated once; changed or ambiguous merchant destinations are retained. The local custom front-page template displays the selected page's editable pattern. Header configuration references a site-local native Navigation record. No source-site numeric identity is imported.

The Cart/Checkout compositions are captured from the pinned WooCommerce installer's public `woocommerce_create_pages` filter while returning an empty definition list, so the capture creates or assigns no pages. The importer then creates its own fixture pages with those real native block trees. It does not use a self-closing empty Cart/Checkout shell or legacy checkout shortcode. Existing native pages are retained.

Download examples are original local text files beneath `woocommerce_uploads` with native forced-download and login-required settings. Direct file access must be checked on the actual host; the local Apache `.htaccess` is created only if absent. This is not a claim of protection on arbitrary hosting stacks.
